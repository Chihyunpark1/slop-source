# Home standings — the prebuilt points summary behind "Top sloperators"

## Target

The home page "Top sloperators" standings table of the public SLOPCASH
codebase (`SlopDotCash/slopdotcash`, MIT), as named in Issue #9
(Cycles & standings): `src/HomeStandings.tsx`,
`src/lib/points-summary.ts`, and the summary publisher
`scripts/generate-points.ts` (`pointsSummary()` / `generatePoints()`).
Live data: the published summary at
`https://slop.cash/data/points-summary.json`.

## Claim

The home standings table never reads the points journal. It reads one
small prebuilt summary, `/data/points-summary.json`, generated by
`scripts/generate-points.ts` alongside the 16-shard journal and bound
to that journal by a SHA-256 digest; the browser validates the file's
shape, re-sorts it by all-time total (ties by locale-aware actor id),
and shows the top 10 with shared ranks for tied totals.

## Evidence

All code references are to `SlopDotCash/slopdotcash` at the
`development` branch.

### 1. The summary is built with the journal, not on request

In `scripts/generate-points.ts`, `generatePoints()` writes the full
journal first (16 shards under `public/data/points/`, plus the index
`public/data/points.json`), then builds the summary from the same
journal members. A comment in the code states the intent plainly:
the home page ranks the top contributors from this small summary
instead of downloading every shard of the journal.

It is published atomically (a `.tmp` file renamed into place).
`pointsSummary()` keeps only contributors with a total above zero,
sorts by total descending with `actor.id.localeCompare` as the
tiebreak, and returns the schema-versioned object: `ruleVersion`
taken from the journal, `generatedAt` taken from the journal,
`indexDigest` (the SHA-256 of the JSON of the points index), totals
(contributor count and the sum of all totals), and one row per
contributor carrying only `actor.id`, `actor.login`, and `total`.

Two consequences: the summary carries all-time totals only (no
per-cycle breakdown), and its `generatedAt` is the journal's
`generatedAt`, not a fresh timestamp — the summary and the journal it
describes are from the same build. The `indexDigest` ties the summary
to the exact journal publication it was derived from.

### 2. The browser validates the file before trusting it

`src/lib/points-summary.ts` defines the `PointsSummary` shape
(`schemaVersion: "1"`, `ruleVersion`, `generatedAt`, 64-hex
`indexDigest`, `totals`, `contributors` with only `actor.id`,
`actor.login`, `total`). `isPointsSummary()` rejects the file unless
all of these hold: `contributors.length` equals
`totals.contributors`, the totals sum to `totals.points`, totals are
non-increasing, every total is greater than zero, and no actor id
repeats.

### 3. The table re-sorts, takes the top 10, and shares ranks on ties

`src/HomeStandings.tsx` fetches `/data/points-summary.json` (4 MiB
cap, `isPointsSummary` check, retry button on failure), re-applies
the same ordering (total descending, ties by actor id via
localeCompare), and renders `HOME_ROWS = 10` rows. Ranks are computed so equal totals
share a rank: a row's rank is its 1-based position when its total
differs from the previous row, otherwise the previous row's rank.
Each row links to `/contributors/<login>`, shows the GitHub avatar,
and links out to the full leaderboard at `/points?period=lifetime`.

### 4. The tiebreak is locale collation, not byte order

Because the tiebreak is `String.localeCompare`, tied contributors are
ordered by locale-aware collation, not by ASCII code units. For
example, at 300 points the live file orders
`MDQ6VXNlcjc2MDM1OTU=` before `MDQ6VXNlcjIzMzk2MTY5`: after the common
prefix `MDQ6VXNlcj`, `c` sorts before `I` under locale collation,
even though `I` (0x49) is smaller than `c` (0x63) in ASCII. Any
reimplementation that sorts ids by code unit will order tied rows
differently.

## Verification

Fetched the live summary on 2026-11-11 (~20:55 KST):

- `curl https://slop.cash/data/points-summary.json` → HTTP 200,
  67,857 bytes (far under the 4 MiB client cap).
- `schemaVersion: "1"`, `ruleVersion: "slop-points-v1"`,
  `generatedAt: 2026-11-10T11:02:50.351Z`,
  `indexDigest` a 64-hex string, 989 contributors, 750,570 points
  total.
- Recomputed in Node: the sum of all contributor totals equals
  `totals.points` (750,570); all 989 actor ids are unique; every
  total is greater than zero; totals are non-increasing.
- Re-sorted the live rows with the same ordering used by
  `pointsSummary()` and `HomeStandings.tsx` (total descending,
  ties by actor id with localeCompare) and the order matched the
  published file exactly — including all 113 tie-adjacent pairs,
  confirming the locale-collation tiebreak.
- Live top 10: lalalune 256,610; NubsCarson 61,750; ss251 47,240;
  hermesagent270-commits 36,870; attentionhead 27,100; 0xSolace
  25,720; WalkCrypto 19,380; standujar 17,630; Chihyunpark1 16,930;
  shawkkkkk 9,000. Rank 11 is 8,610, so no tie straddles the top-10
  cutoff in this snapshot.

## Notes

- Not covered here: how journal totals are computed from score
  events (the points rules, Issues #2 / #17); how the leaderboard
  page assembles the full journal (per the docstring in
  `src/lib/points-summary.ts`, it still reads every shard); cycle
  snapshots and winner determination (other slices of Issue #9).
- The summary is a build artifact: it is only as fresh as the last
  `generate-points.ts` run, and the home page shows a "Top
  contributors are unavailable" state with a retry button when the
  fetch or the validation fails.
